## نتيجة التحقق

| دورة تسجيل وتفعيل ودخول ببيانات تجريبية توافق الـ API الجديدة | نجحت باستدعاء controllers مباشرة؛ استُخدمت لاختبار اختلاف طلبات الواجهة |

## المشاكل المؤكدة حسب الأولوية

1. **[P1] السيرفر لا يبدأ بسبب عدم تحديث الربط بعد تغيير الـ exports.**

   ملف [authRoutes.js](/Users/abdoadel/Porgraming/Projects/Attend/backend/routes/authRoutes.js:3) يستورد `registerUser` و`loginUser`، بينما [authController.js](/Users/abdoadel/Porgraming/Projects/Attend/backend/controllers/authController.js:95) يصدّر `createAuthController` فقط. النتيجة الفعلية: `Route.post() requires a callback function but got a [object Undefined]`. نفس عدم التوافق موجود في بقية routes والـ middleware. كذلك [server.js](/Users/abdoadel/Porgraming/Projects/Attend/backend/server.js:11) يستدعي `initDB` التي لم تعد موجودة؛ [database.js](/Users/abdoadel/Porgraming/Projects/Attend/backend/db/database.js:40) يصدّر `openDatabase`. المطلوب إنشاء config وstore وauth والـ controllers وربطها بالـ routes، مع انتظار فتح قاعدة البيانات قبل تشغيل السيرفر.

2. **[P1] تسجيل الدخول يرسل اسم المستخدم بينما السيرفر يطلب البريد.**

   [AuthContext.tsx](/Users/abdoadel/Porgraming/Projects/Attend/contexts/AuthContext.tsx:106) يرسل `{ name, password }`، لكن [authController.js](/Users/abdoadel/Porgraming/Projects/Attend/backend/controllers/authController.js:27) يتحقق من `body.email`. تمرير طلب الواجهة مباشرة إلى controller أعطى خطأ validation بحالة 400 قبل فحص كلمة المرور. يجب تحديث الحقل والطلب ليستخدما البريد.

3. **[P1] الواجهة لا تتعامل مع نظام الجلسات الجديد، والخروج لا يلغي جلسة السيرفر.**

   [AuthContext.tsx](/Users/abdoadel/Porgraming/Projects/Attend/contexts/AuthContext.tsx:115) يتوقع `data.token` ويخزنه في localStorage، بينما الدخول الجديد يرجع cookie و`csrfToken` دون `token` في جسم الرد. [authMiddleware.js](/Users/abdoadel/Porgraming/Projects/Attend/backend/middleware/authMiddleware.js:8) يقرأ cookie ويشترط `X-CSRF-Token` للعمليات التي تغيّر البيانات. الطلبات الحالية ترسل Bearer فقط؛ في تجربة منفصلة رُفض Bearer دون cookie بحالة 401، ورُفض طلب تعديل مع cookie ودون CSRF بحالة 403. الـ cookie يمكن أن يصل تلقائيًا عبر proxy، لكن ذلك لا يعالج CSRF أو اعتماد الواجهة على token. كذلك [logout](/Users/abdoadel/Porgraming/Projects/Attend/contexts/AuthContext.tsx:59) يمسح الحالة المحلية فقط، ولا يستدعي إلغاء الجلسة. يلزم تحديث دورة الدخول واستعادة الجلسة والخروج وطلبات التعديل معًا.

4. **[P1] إعداد حساب الشركة غير متوافق مع البيانات المطلوبة.**
